# 日本展览目录与观展记录

`#exhibitions` 默认日本，可切换现有的海外活动或全球。日本目录独立存放。同一场展上了新闻，也不会从目录另生成一篇待译报道。

## 怎样接近完整

- Internet Museum 按 47 个都道府县分别翻页，将每个地区公布的总数与实际读到的唯一活动链接对照。目录明确显示零条只说明这个来源没有登记。
- Tokyo Art Beat 全国页达到上限时，遍历其公开地区搜索的 65 个分区及后来观察到的分区。将合并后的唯一链接数与全国目录公布的总数核对，并保存每个分区的核对结果。
- 美術展ナビ沿公开的下一页读取至末页。重复分页、读取失败、部分条目无法解析、访问限制和请求预算都进入报告。已取得的条目和历史库存保留。
- 已验证场馆日历直接补入。补源时优先查「无独立官网日历」或目录长期为空的地区，以 [Art Platform Japan 机构名录](https://artplatform.go.jp/museums) 为一份底册，再扩展当地画廊、艺术节主办方、驻地与独立艺术空间。确认公开日历页、活动类型与页面解析后更新源配置。
- 分类可多选，包含绘画与版画、装置、摄影、雕塑、影像与媒体、设计和工艺、历史及古美术、漫画与艺术节；没有足够信息时保留在「综合／待分类」。从明确的目录标签或展名判断类型。只有能明确区分的独立讲座、工作坊、音乐活动才排除。

去重依赖展名、场馆、地区和展期。同名巡展的不同场馆以及后续不同届次保留为独立活动。合并后保留各来源链接及其原展期，场馆官网优先，冲突明示。如果没有可靠的年份或日子，保留待确认。结束或暂时未能再次抓到的活动不会删除，个人记录依旧指向原 ID。

线上 `/reports/japan-exhibitions.json` 可独立核对逐县页数、公布数、实际读到条数、故障、零条结果和官网日历进度。目录对账只能验证所接来源的公开登记范围，离线公告、未登记的画廊与快闪空间等仍可能漏收。

## 什么先看

「值得留意」综合回顾展、艺术节、重要周年或规模、场馆官网列出的企划展等明示信号，再按近期开闭展、关注对象等排序。全国推荐最多 6 场，同场馆最多 1 场，同都道府县最多 2 场；完整重点展有单独入口。媒体流量、评论数和其他人的评分不参与。连续 14 天未再见的展览、常设展和暂定展期保留在清单。

「7 天内闭展」在首屏提供独立入口，想去的在提醒区优先；日本用东京日期，其他地区用当地日期。延期、取消、暂定或缺闭展日的项目不做确定倒计时。若同时有两个日期，提示可能更早的闭展日并附官网核对。去过、不感兴趣的活动从推荐区移出，仍能按个人标签或在展览清单中找到。清单支持范围、都道府县、类型、展期、个人标签及搜索，并可切换排序。

## 记录和更新

想去、去过、不感兴趣互斥，收藏独立。笔记最多 4000 字，评分为 1–5 分。「我的观展记录」可回查，备份文件包括全部字段。在公开站及本地服务版中，记录仅保存在当前浏览器的 `culture-desk-exhibition-log-v1`。原「剪报」仍在原入口。

`config/exhibitions-jp.json` 管理公开目录、地区表、场馆页和别名。采集命令 `python scripts/collect_exhibitions.py` 仅写 `data/exhibitions-jp.json`。独立 GitHub Actions 计划按东京 06:20 和 18:20 运行，实际时点受 GitHub 调度影响。分站限流，跨站并行，更新成功后发布目录和覆盖报告。静态网页只在进入展览页后读目录，便携单文件预览内联，本地 FastAPI 使用 `/api/japan-exhibitions`。
