# T034 后端与浏览器数据优化 · 2026-10-14

定位：面向公众查询、阅览的艺术新闻资讯平台；GitHub Pages公开阅读，浏览器收藏/偏好为辅助。后端采集、翻译队列及完整原文档案保持，不把界面精简变成删资料。

## 536条未变化记录的实测

相同公开快照先恢复到临时SQLite，随后以相同记录模拟一次重复采集。两轮均inserted=0、updated=0。数值是这次本地受控样本，不是全天端到端吞吐量。

| 指标 | 改前 | 改后 |
| --- | ---: | ---: |
| UPDATE content语句数 | 23,048 | 536 |
| 重复采集耗时（单次） | 0.2533秒 | 0.0535秒 |
| 浏览器data.js未压缩字节 | 8,317,577 | 5,787,811 |

每条未变化记录由逐字段更新改成一次参数化UPDATE，保留缓存正文/译文及必要元数据，依旧在同一事务中回滚或提交。覆盖统计把已完成对象建集合、文章按来源一次分组，避免反复比较整份正文和每个来源重复扫描全库。

## 传输精简与兼容性

新增backend/presentation.py的browser_snapshot，仅处理浏览器传输副本；data/live.json、数据库、翻译输入、原文块和中文译文不删改。计算覆盖/优先级报告时仍用完整快照。

- article_text仅在它可由不超过2000个合法正文块精确重建时省去；格式异常、长度超限或存在额外全文时保留。
- 浏览器不携带未展示的旧逐句机翻正文、初稿、审核过程JSON；editorial_status、实际模型、译文和必要说明仍保留，完整档案中仍有原字段。
- JSON采用紧凑序列化；不是摘要替代全文，也没有按来源删减。
- CultureCore.sourceText(row)优先用已有article_text，否则从保存原文块重建。WeakMap按对象及块内容缓存，块改动时失效。查询仍覆盖全部原文正文，不限当前分页。
- 本地API仍返回原有完整数据形态，浏览器支持两种形态。其他AI不应假定data.js含重复article_text，使用sourceText和articleBlocks。

逐条核验536条原文块、译文块、重建搜索文本与完整档案一致。测试包含无正文、非标准块、超2000块回退、缓存失效及一条未变化采集只产生一次UPDATE、保留译文和正文。

没有改变已有账户/凭据、公开托管、浏览器收藏格式、活动时区、采集频率或翻译模型，不调用付费模型API。SQL语句减少不能当作所有后台任务同倍数变快；采集耗时仍受网络与来源状态影响。
