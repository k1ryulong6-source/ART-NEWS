# 需求与决策记录

## D001 · 用户确认 · 2026-10-13

个人平台覆盖电影、艺术、摄影，重视中日资讯、日本上映情报和日本新展。用途是发现、阅读、收藏与安排观影／看展。

## D002 · 用户确认 · 2026-10-13

不要器材评测；加入一点八卦新闻。实现为相关领域的圈内动态，保持少量、可关闭、可追溯出处。

## D003 · 用户确认 · 2026-10-13

项目需要允许其他 AI 加入建设，并在当前 AI 额度用完时接力。采用文件化需求、任务、数据契约和实时交接记录；不依赖聊天记忆。

## D004 · 可调整默认 · 2026-10-13

中文界面；日本默认东京，中国默认上海／北京；每日精选十条，圈内动态上限一条。用户没有最终确认城市、精选条数或比例，均可通过设置调整。

## D005 · 技术建议 · 2026-10-13

建议 React／TypeScript／Vite + Python／FastAPI + SQLite，先本地原型。当前只建立 SQL 与基础包，不宣称应用已实现。另一个 AI 若有更合适路线，可记录原因后调整。

## D006 · 数据约定 · 2026-10-13

报道与活动分离；不同地区上映独立；日本活动使用当地日期；来源未核实默认关闭；示例显式标记。

## D007 · 实施调整 · 2026-10-13

第一版前端采用无依赖原生 HTML／CSS／JavaScript，替代尚未开始安装的 React／Vite 建议。原因是降低换 AI／换环境时的安装成本，并提供离线可直接打开的单文件演示。后端沿用 FastAPI + SQLite，依赖按实际环境版本锁定。

同一界面自动选择本地服务 API 或浏览器存储；两套状态相互独立，通过 JSON 导出／恢复迁移。静态版并不具备后台采集能力。生成的数据包完全为显式标注的虚构示例。

## D008 · 验证状态 · 2026-10-13

浏览器启动被当前环境的套接字权限限制阻止；不重复发起导致长时间等待的权限请求。API 使用无 TCP 监听的 ASGI HTTP 检查验证，界面布局与真实浏览器交互留作明确待验收项。当前未注册／发布 Sites；其源码工作流脚本未在本工作区找到，不绕过源码同步流程直接声称发布。

## 待实际建设确定

- 用户主要居住／出行城市与关注名单。
- 首批真实来源及可用接入方法。
- 摘要模型、费用预算、正式部署位置与访问方式。
- 通知渠道；第一版优先站内提示，邮件后续配置。

这些选择不会阻止制作示例原型，不能假定用户已经授权某个收费账号或指定外部发布地点。
